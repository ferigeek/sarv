# طراحی پایگاه داده

## نمای کلی

این پروژه از PostgreSQL به عنوان پایگاه داده اصلی برای یک پلتفرم شبکه اجتماعی استفاده می‌کند.  
این پایگاه داده برای مدیریت کاربران، پست‌ها، تعاملات، رسانه‌ها و ثبت رویدادها جهت تحلیل و یادگیری ماشین طراحی شده است.

## موجودیت‌های اصلی

### کاربران (Users)
اطلاعات حساب کاربری و پروفایل کاربران را نگهداری می‌کند.

فیلدهای مهم:
- id (کلید اصلی)
- username (یونیک)
- email (یونیک)
- password_hash
- status (active, suspended, banned, deleted)
- gender (enum)
- profile_picture (ارجاع به media)

### پست‌ها (Posts)
نمایانگر محتوای تولید شده توسط کاربران است.

انواع پست:
- پست معمولی (NORMAL)
- کامنت (COMMENT) از طریق parent_id
- بازنشر (REPOST) از طریق repost_of_id
- نقل‌قول (QUOTE) همراه با ارجاع به یک پست دیگر

هر پست متعلق به یک کاربر است.

پست‌ها همچنین شمارنده‌های تجمیعی دارند که توسط بک‌اند نگهداری می‌شوند:

- view_count (با هر مشاهده تکی پست و برای هر پستی که از فید سرو شود افزایش می‌یابد)
- like_count / dislike_count (با افزودن، حذف یا تغییر واکنش به‌روزرسانی می‌شوند)
- comment_count (با ایجاد COMMENT روی پست به‌صورت اتمیک افزایش می‌یابد؛ افزوده‌شده در V6)

### واکنش‌ها (Reactions)
واکنش کاربران به پست‌ها را ذخیره می‌کند.

- reaction_type:
  - 1 = لایک
  - -1 = دیسلایک
- هر کاربر فقط یک واکنش برای هر پست می‌تواند ثبت کند (unique constraint)

### دنبال‌کردن (Follows)
ارتباط دنبال‌کننده و دنبال‌شونده را نگهداری می‌کند.

- follower_id → کاربر دنبال‌کننده
- followed_id → کاربر دنبال‌شونده
- جلوگیری از ثبت تکراری رابطه (محدودیت یکتا روی follower_id + followed_id)
- دنبال‌کردن خود با یک محدودیت CHECK (follower_id <> followed_id) رد می‌شود

### رسانه‌ها (Media)
اطلاعات فایل‌های آپلود شده را نگهداری می‌کند. خود فایل روی فایل‌سیستم محلی بک‌اند و با کلید هش SHA-256 آن ذخیره می‌شود؛ پایگاه داده فقط فراداده را نگه می‌دارد.

شامل:
- اندازه فایل
- نوع MIME
- هش SHA-256 (یکتا؛ همچنین به عنوان کلید ذخیره‌سازی استفاده می‌شود و حذف تکراری را ممکن می‌کند)
- مالک فایل

### لاگ رویدادها (Event Logs)
برای ثبت رفتار کاربران جهت تحلیل و یادگیری ماشین استفاده می‌شود.

کاربردها:
- رتبه‌بندی فید
- تحلیل رفتار کاربران
- سیستم پیشنهاددهی

نمونه رویدادها:
- LOGIN
- VIEW_POST
- LIKE_POST
- CREATE_POST
- FOLLOW_USER
- REQUEST_FEED

شناسه کاربر می‌تواند NULL باشد (برای ناشناس‌سازی داده‌ها).

فیلدهای اضافه‌شده (در مهاجرت V4):

- session_id (UUID) — کنش‌های یک نشست کاربری را گروه‌بندی می‌کند؛ بی‌رابطه با احراز هویت JWT
- metadata (JSONB) — اطلاعات اضافی خاص هر رویداد که ستون جداگانه نمی‌خواهد

## روابط بین جداول

- هر کاربر می‌تواند چندین پست ایجاد کند
- هر کاربر می‌تواند چندین دنبال‌کننده و دنبال‌شونده داشته باشد
- هر کاربر می‌تواند چندین واکنش ثبت کند
- هر پست می‌تواند چندین واکنش داشته باشد
- پست‌ها می‌توانند کامنت داشته باشند (ارتباط بازگشتی)
- پست‌ها می‌توانند نقل‌قول از پست دیگر باشند (QUOTE)
- هر فایل رسانه‌ای می‌تواند متعلق به یک کاربر باشد
- رویدادها می‌توانند به کاربر، پست یا کاربر هدف مرتبط باشند

---

## استراتژی حذف داده‌ها

- کاربران: حذف کامل پست‌ها، دنبال‌ها و واکنش‌ها (CASCADE)
- پست‌ها: در صورت حذف کاربر حذف می‌شوند
- رسانه‌ها: مالک حذف شود → مقدار NULL می‌شود
- لاگ‌ها: کاربر حذف شود → مقدار user_id برابر NULL می‌شود (برای حفظ داده‌های تحلیلی)

## ایندکس‌ها (پیاده‌سازی‌شده)

PostgreSQL به صورت خودکار ستون‌های کلید خارجی را ایندکس نمی‌کند و محدودیت‌های یکتای موجود نیز همه الگوهای جست‌وجو را پوشش نمی‌دهند. ایندکس‌های زیر توسط مهاجرت `V5` ایجاد شده‌اند:

- follows (followed_id) — فهرست دنبال‌کننده‌ها
- posts (user_id, created_at) — خط زمانی کاربران / جست‌وجوی فید، جدیدترین اول
- posts (parent_id) — پیمایش درخت کامنت‌ها
- posts (repost_of_id) — پیمایش بازنشرها
- reactions (user_id) — تاریخچه واکنش‌های هر کاربر (مکمل محدودیت یکتای post_id + user_id)
- event_logs (user_id, created_at) — خط زمانی فعالیت هر کاربر برای تحلیل
- event_logs (type, created_at) — تجمیع‌های موضوعات داغ / زمان اوج استفاده
- event_logs (post_id), event_logs (target_user_id) — پرس‌وجوهای تحلیلی مبتنی بر موجودیت

## نکات

- لاگ‌های رویداد برای سیستم یادگیری ماشین و پیشنهاددهی استفاده می‌شوند
- حذف نرم (soft delete) از طریق deleted_at در پست‌ها و رسانه‌ها پشتیبانی می‌شود
- طراحی پایگاه داده برای بار خواندن بالا (feed system) بهینه شده است
